# 12. Мини-дашборд

[Программа](../README.md) · [Далее: React + TypeScript](13-react-typescript.md)

Собери компоненты курса в одно небольшое приложение. Цель — реализовать самостоятельную продуктовую функцию от загрузки до обработки ошибки.

## Теория перед работой

Раздели загрузку, преобразование данных и отображение. Компонент уведомлений не должен напрямую менять DOM таблицы: действие обновляет общее состояние, после чего нужные части получают новые данные. Один источник истины снижает риск расходящихся счётчиков и экранов.

`Promise.all` ожидает все операции, но отклоняется при первой ошибке. Для независимых секций удобно `Promise.allSettled`: успешная таблица останется доступной даже при ошибке каталога. Запросы запускай параллельно, а не после ожидания предыдущего. [Promise](https://doka.guide/js/promise/), [async/await](https://doka.guide/js/async-await/), [fetch](https://doka.guide/js/fetch/).

Данные пользователя храни как текст, а настройки — в localStorage с обработкой недоступности и повреждённого JSON. У компонентов нужен жизненный цикл: создание, обновление, уничтожение. Таймеры, document-подписки и fetch должны завершаться или отменяться при уничтожении. Повтори [области видимости](https://doka.guide/js/closures/) и [localStorage](https://doka.guide/js/local-storage/).

## Мини-упражнение

Запусти два Promise: один успешный, один с ошибкой. Сравни all и allSettled, нарисуй на бумаге, какие секции останутся видимыми. Затем повтори с успешными результатами в обратном порядке.

## Задание

1. Параллельно загрузи товары и пользователей через fetch по [контрактам курса](api-practice.md). Для каждой секции — собственные loading/error/empty/success и повтор; ошибка одной не скрывает успешную другую.
2. Метрики показывают именно количество загруженных записей N/M; рядом укажи серверный total. Не называй выборку полным количеством базы.
3. Включи карточку профиля, вкладки, FAQ, центр уведомлений, диалог, тосты, autocomplete, каталог с фильтрами и таблицу. Форма регистрации здесь становится учебной формой редактирования профиля: используй навыки подписей и ошибок, пароли в localStorage не сохраняй.
4. Добавь локальное «Скрыть товар». Диалог подтверждает действие; после подтверждения товар исчезает из каталоговой выборки, метрика обновляется, тост сообщает успех. ID скрытых товаров храни отдельно. API не изменяется, и UI явно обозначает действие как локальное.
5. Добавь «Восстановить скрытые»: возвращает записи, обновляет счётчики. Данные профиля и список скрытых ID переживают перезагрузку. Некорректное хранилище не ломает запуск.
6. Раздели URL-параметры каталоговой и табличной панелей: например `catalogQ`, `usersQ`, `usersPage`, плюс `tab`. Компоненты не удаляют параметры друг друга; состояние открывается по ссылке и восстанавливается через историю.
7. В README объясни границы компонентов, контракты API и сценарии проверки. Не превращай все события в один обработчик с десятками условий.

## Самопроверка и ревью

- [ ] Полный сценарий: загрузка → фильтр → скрытие → отмена/подтверждение → тост → восстановление.
- [ ] Один endpoint временно блокируется в DevTools: другой раздел продолжает работать.
- [ ] Смена панели во время загрузки не открывает старый поиск и не крадёт фокус.
- [ ] Перезагрузка и Назад/Вперёд восстанавливают ожидаемое состояние.
- [ ] На 360px и при 200% остаются доступны все действия.
- [ ] Нет дублирующихся ID, лишних подписок и необработанных отклонений Promise.

Для основных чистых функций добавь небольшие автоматические проверки: фильтр с ценой 0, пагинация на последней странице, сортировка без мутации. Для жизненного цикла проверь, что устаревший запрос не меняет UI после уничтожения. Инструмент выбирай по среде; проверки должны ловить ошибки поведения.

Усложнение: сохранение выбранных колонок таблицы, отдельные настройки темы и проверка в двух браузерах.
