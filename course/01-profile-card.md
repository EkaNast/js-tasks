# 01. Карточка профиля

[Программа](../README.md) · [Далее](02-registration-form.md)

Сделай карточку разработчика: это первая практика семантики, блочной модели и раскладки. JavaScript не нужен.

## Теория перед работой

Независимую карточку можно разметить `<article>` с заголовком. Фото получает `alt`, описывающий его назначение; декоративное изображение — пустой `alt`. Ссылки позволяют перейти к проектам и написать письмо через `mailto:`. Теги навыков удобно оформить списком.

Flexbox распределяет элементы вдоль основной оси, `align-items` выравнивает по поперечной. `gap` задаёт промежутки без отступа у края. `max-width` ограничивает ширину, но оставляет карточке возможность сжиматься. Учитывай padding и рамку через `border-box`. Для переносимого длинного текста пригодится `overflow-wrap`; у flex-элемента автоматическая минимальная ширина иногда мешает сжатию, тогда проверь `min-width: 0`.

Прочитай: [семантика](https://doka.guide/html/semantics/), [box-sizing](https://doka.guide/css/box-sizing/), [Flexbox](https://doka.guide/css/flexbox-guide/). Найди в статьях выбор тега, оси контейнера и расчёт ширины.

## Мини-упражнение

Сделай блок шириной 240px с padding 16px и рамкой 2px. Посчитай внешнюю ширину при двух значениях `box-sizing`, затем проверь в DevTools. Добавь два конфликтующих правила цвета: объясни победившее.

## Задание

1. Добавь один `h1` страницы и логичный заголовок карточки, фото, описание, три навыка и две настоящие ссылки. Проекты могут вести к отдельному блоку этой же страницы.
2. Сверстай широкую и мобильную версии по схеме. Внутренний padding 24px, между смысловыми группами 16px. Аватар квадратный, изображение не искажается.
3. Сделай состояния ссылок hover и focus-visible. Порядок DOM должен совпадать с чтением сверху вниз.
4. Карточка сжимается по контейнеру; длинное имя и описание не обрезаются и не перекрывают ссылки.
