# 11. Таблица пользователей

[Программа](../README.md) · [Далее](12-mini-dashboard.md)

Сделай таблицу данных из API с поиском, сортировкой, пагинацией и состоянием в URL.

## Теория перед работой

Табличные данные размечаются через `table`, `caption`, `thead`, `tbody`, `tr`, `th`, `td`. Заголовкам колонок нужен `scope="col"`. Сортируемый заголовок содержит кнопку, а `aria-sort` у `th` описывает текущий порядок. Не заменяй таблицу набором div ради внешнего вида. [Дока: таблицы](https://doka.guide/html/tables/).

Порядок обработки: исходные данные → filter → sort → slice страницы. Если сначала взять страницу, поиск и сортировка затронут лишь её. При размере страницы 10 начало равно `(page - 1) * 10`, конец — `page * 10`. Число страниц считай из отфильтрованного количества, а не из серверного total всей базы. [Filter](https://doka.guide/js/array-filter/), [sort](https://doka.guide/js/array-sort/).

`position: sticky` требует порога, например `top: 0`, и зависит от прокручиваемого контейнера. На телефоне прокручивай таблицу внутри отдельной области, сохраняя семантику. [Position](https://doka.guide/css/position/), [overflow](https://doka.guide/css/overflow/).

Для URL используй модель предыдущей задачи. При изменении поиска сбрасывай страницу в 1, при некорректном номере ограничивай его допустимым диапазоном. [URLSearchParams](https://doka.guide/js/urlsearchparams/), [fetch](https://doka.guide/js/fetch/), [практика API](api-practice.md).

## Мини-упражнение

Напиши `paginate(items, page, pageSize)`. Проверь пустой список, одну запись, 21 запись при размере 10, страницу -1 и страницу 999. Отдельно договорись, что при нуле результатов UI не показывает «страница 1 из 0».

## Макет

```text
Пользователи                     [Обновить]
Загружено N из total
Поиск [_______________________________]
┌───────────────┬───────────────┬──────────┬─────────┐
│ Имя ↑         │ Email         │ Роль     │ Возраст │
├───────────────┼───────────────┼──────────┼─────────┤
│ Имя Фамилия   │ user@…        │ admin    │ 28      │
│ Другой человек│ other@…       │ user     │ 31      │
└───────────────┴───────────────┴──────────┴─────────┘
Показано 1–10 из M       [Назад] Страница 1 / K [Далее]
360px: поиск и пагинация в колонку;
таблица прокручивается по горизонтали внутри своей области.
```

## Данные

Запроси `https://dummyjson.com/users?limit=100&select=id,firstName,lastName,email,role,age`. Используй `users`, объедини firstName/lastName для колонки имени. В этой версии нет выдуманных дат создания или статусов блокировки: таблица показывает поля реального учебного ответа. [Документация пользователей](https://dummyjson.com/docs/users).

## Задание

1. Загрузку делай через fetch. Покажи loading, error с повтором, empty для успешного пустого результата, success. Поиск работает по имени и email без учёта регистра.
2. Сортируй имя и возраст в обе стороны, при равенстве используй ID как стабильный дополнительный критерий. Возраст сравнивай численно. Пагинация — по десять записей.
3. Сохраняй `q`, `page`, `sort=name|age`, `direction=asc|desc` в URL. Начальные значения: пустой поиск, страница 1, имя по возрастанию. Поддержи Назад/Вперёд.
4. При обновлении данных отмени предыдущую загрузку, проигнорируй устаревший результат. Не допускай смешения двух ответов.
5. Сделай sticky-заголовки в контейнере высотой до 400px; область прокрутки доступна клавиатурой и имеет понятное имя. Кнопки пагинации на границах disabled, текущая сортировка понятна без цвета.
6. Поиск и сортировка применяются ко всем загруженным записям, затем выбирается страница. Явно покажи N из total согласно [правилам API](api-practice.md).

## Самопроверка и ревью

- [ ] HTTP- и сетевые ошибки обработаны, повтор создаёт рабочий запрос.
- [ ] Последняя неполная страница не содержит лишних строк; ноль результатов не показывает неверный диапазон.
- [ ] `?page=-2&sort=unknown` приводит к валидному состоянию.
- [ ] Смена сортировки не меняет исходный массив, стрелка и aria-sort согласованы.
- [ ] После быстрого обновления поздний ответ не перезаписывает новые данные.
- [ ] Длинный email переносится или доступен внутри области прокрутки.

Усложнение: серверная пагинация через `limit` и `skip`, серверный поиск `/users/search?q=...`. Перед реализацией уточни поддерживаемые параметры в документации: нельзя сортировать только текущую страницу и выдавать это за сортировку всей базы.
