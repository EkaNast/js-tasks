# 08. Поиск с подсказками

[Программа](../README.md) · [Далее](09-product-grid.md)

Сделай поиск товаров через `fetch` с задержкой ввода и защитой от устаревших результатов. Перед началом прочитай [практику работы с API](api-practice.md).

## Теория перед работой

Promise описывает будущий результат: fulfilled или rejected после pending. `await` приостанавливает продолжение async-функции, а не весь браузер. `try/catch` обрабатывает ошибку; отмену запроса не следует показывать как сбой. [Promise](https://doka.guide/js/promise/), [async/await](https://doka.guide/js/async-await/).

Debounce перезапускает таймер при каждом вводе и вызывает поиск после паузы. Throttle ограничивает частоту вызовов при непрерывном потоке; для этой задачи нужен именно debounce. [Дока: debounce](https://doka.guide/js/debounce/).

Ответы могут прийти в обратном порядке. Отменяй предыдущую операцию через `AbortController` и проверяй номер актуального запроса перед изменением UI. Проверка нужна также в `catch/finally`, иначе старый запрос способен сбросить новый loading. При изменении ввода сразу сделай прежний запрос неактуальным, ещё до ожидания debounce. [AbortController](https://doka.guide/js/abort-controller/).

Для подсказок используй модель combobox: поле с `role="combobox"`, `aria-expanded`, `aria-controls`, `aria-autocomplete="list"`; список `listbox`, варианты `option`. Фокус остаётся в поле, активный вариант указывается через `aria-activedescendant` и уникальный ID. [Дока: input](https://doka.guide/html/input/), [WAI-ARIA Combobox Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/).

## Мини-упражнение

Напиши `debounce(fn, 300)`. Вызови обёртку со значениями `r`, `re`, `rea` с промежутками 100ms: до паузы вызовов `fn` быть не должно, после неё — один с `rea`. Сделай метод отмены отложенного вызова.

## Данные и контракт поиска

Обязательный источник — [DummyJSON: поиск товаров](https://dummyjson.com/docs/products). Запрос: `https://dummyjson.com/products/search?q=phone&limit=5`. Ответ — объект с `products`, `total`, `skip`, `limit`; это не массив на верхнем уровне.

Самостоятельно реализуй `search(query, { signal })`, вызывающую `fetch` и возвращающую Promise массива `{ id, name }`: преобразуй `products[].title` в `name`, сохрани ID. Параметр `q` собирай через `URLSearchParams`. Проверяй `response.ok` до чтения JSON и передавай `signal` в fetch. Названия на схеме условные: показывай фактические данные ответа.

## Задание

1. Запускай поиск через 300ms после ввода минимум двух символов без крайних пробелов. Укороченный или пустой ввод отменяет таймер и запрос, очищает результаты.
2. Покажи все пять состояний из схемы. «Повторить» запускает текущий запрос заново. Устаревший успех или ошибка не меняет экран.
3. ArrowDown/ArrowUp меняют активный вариант, Enter выбирает, Escape закрывает список. Клик также выбирает; учти, что blur поля может наступить раньше click по варианту.
4. Покажи выбранное название, обнови значение поля и закрой список. Длинная строка не расширяет компонент, активная опция прокручивается в видимую область.
5. Закрытие по Escape делает текущую операцию неактуальной, чтобы поздний ответ сам не открыл список. Добавь очистку при уничтожении компонента.

## Самопроверка и ревью

- [ ] Быстрый ввод создаёт один вызов после паузы; очистка не запускает отложенный поиск.
- [ ] В Network виден настоящий запрос поиска, передающий строку пользователя.
- [ ] Для воспроизводимой проверки подставь тестовую функцию поиска: ответ `ph` через 900ms, `phone` через 100ms. Начни `ph`, через 350ms введи `phone`: поздний ответ `ph` не заменяет результаты. После проверки верни fetch.
- [ ] Отмена не выводит error, старый finally не снимает новый loading.
- [ ] Запрос случайной длинной строки даёт empty; Offline в DevTools — error. После возврата Online повтор работает.
- [ ] Выбор клавиатурой и мышью работает, `aria-activedescendant` не ссылается на удалённую опцию.

Усложнение: добавь кеш успешно полученных результатов по нормализованному запросу и ограничь его 20 записями. Ошибки и отмены не кешируй.
