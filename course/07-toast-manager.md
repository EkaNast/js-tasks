# 07. Менеджер тостов

[Программа](../README.md) · [Далее](08-autocomplete.md)

Сделай небольшие уведомления с очередью и автоматическим закрытием.

## Теория перед работой

`setTimeout` планирует callback после задержки: точное время выполнения не гарантируется. `clearTimeout` отменяет ещё не выполненный таймер. Каждому тосту нужен собственный ID и таймер; после ручного закрытия таймер очищается. [SetTimeout](https://doka.guide/js/settimeout/).

Очередь ожидающих и список видимых — разные коллекции. Освободилось место — покажи старейший ожидающий тост. Замыкание позволяет экземпляру менеджера хранить свои коллекции, не делая их глобальными. [Области видимости](https://doka.guide/js/closures/).

Создавай DOM через `createElement`; пользовательский текст вставляй через `textContent`, чтобы он оставался текстом. Плавное появление можно оформить через opacity/transform и transition. Для `prefers-reduced-motion: reduce` убери движение. Тост сообщает о событии, поэтому не забирает фокус. Для обычных сообщений подготовь заранее существующую область `role="status"`; срочные ошибки допускают `role="alert"`. Не озвучивай все сообщения повторно при обновлении списка. [Transition](https://doka.guide/css/transition/), [media](https://doka.guide/css/media/).

## Мини-упражнение

Создай кнопку «Показать через секунду» и кнопку отмены. Несколько планирований должны заменять предыдущее. Затем создай две независимые копии и проверь изоляцию таймеров.

## Задание

Реализуй собственный API:

```js
const id = toast('Сохранено');
toast('Связь потеряна', { type: 'error', timeout: 5000 });
closeToast(id);
```

1. Поддержи `success`, `error`, `info`; по умолчанию `info` и 4000ms. `timeout: 0` означает только ручное закрытие. Возвращай уникальный ID.
2. Одновременно показывай максимум три тоста. Остальные ожидают FIFO; отсчёт их таймера начинается при показе, а не при добавлении в очередь.
3. Ручное и автоматическое закрытие используют один путь удаления. Повторное закрытие и неизвестный ID безопасно ничего не делают. `closeToast` должен удалять также ожидающий тост.
4. Добавь доступные названия крестикам, анимацию и вариант без движения. При ручном закрытии с клавиатуры направь фокус на следующий крестик или последнюю кнопку, которая создала тост.
5. Добавь `destroy()`, очищающий таймеры, DOM и подписки.

## Самопроверка и ревью

- [ ] После добавления пяти видны три; четвёртый появляется после освобождения места.
- [ ] После ручного удаления старый таймер не удаляет другой тост.
- [ ] Строка `<b>тест</b>` показана буквально, не становится разметкой.
- [ ] При выключенной анимации очередь всё равно продвигается.
- [ ] `destroy()` не оставляет отложенных изменений страницы.

Усложнение: при hover и focus приостанавливай таймер, затем возобновляй на оставшееся время, а не на весь первоначальный timeout.
